# 테스트 계획 — Charapedia

## 실행 환경
- 백엔드: REST API 직접 호출 테스트 (Postman 또는 curl)
- 프론트엔드: 브라우저에서 수동 기능 테스트
- TypeScript: `getDiagnostics`로 타입 에러 0건 확인 (매 Phase)

---

## Phase 1. 인증

### T-AUTH-01. 회원가입
- [ ] 정상 가입 → 201, token + user 반환
- [ ] 이메일 중복 → 409 에러
- [ ] 비밀번호 8자 미만 → 400 에러
- [ ] 필수 필드 누락 → 400 에러

### T-AUTH-02. 로그인
- [ ] 정상 로그인 → 200
- [ ] 존재하지 않는 이메일 → 401 에러
- [ ] 비밀번호 불일치 → 401 에러

### T-AUTH-03. 토큰 복원
- [ ] 로그인 후 새로고침 → 로그인 상태 유지
- [ ] 만료된 토큰 → 자동 로그아웃

## Phase 2. 작품 및 캐릭터

### T-WORK-01. 작품
- [ ] 작품 목록 조회 → 200
- [ ] 작품 등록 → 201
- [ ] 비로그인 작품 등록 → 401 에러

### T-CHAR-01. 캐릭터 목록/검색
- [ ] 전체 목록 조회 → 200
- [ ] work_id 필터 → 해당 작품 캐릭터만 반환
- [ ] search 파라미터 → 이름 부분 일치 결과 반환
- [ ] like_count가 likes 테이블 COUNT와 일치하는지 확인

### T-CHAR-02. 캐릭터 등록/수정/삭제
- [ ] 로그인 사용자 등록 → 201
- [ ] 비로그인 등록 시도 → 401 에러
- [ ] 본인 캐릭터 수정 → 200
- [ ] 타인 캐릭터 수정 시도 → 403 에러
- [ ] 본인 캐릭터 삭제 → 200, 연관 likes/reviews/reports도 삭제 확인
- [ ] admin이 타인 캐릭터 삭제 → 200 (권한 허용 확인)
- [ ] 일반 사용자가 타인 캐릭터 삭제 시도 → 403 에러

### T-CHAR-03. 캐릭터 상세
- [ ] 정상 조회 → isLiked, created_by_me, reviews 포함
- [ ] 비로그인 조회 → isLiked = false
- [ ] 존재하지 않는 id → 404 에러
