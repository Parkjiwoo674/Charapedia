# 요구사항 명세서 — Charapedia (웹소설 캐릭터 도감 + 팬 커뮤니티)

## 1. 개요

웹소설/웹툰 캐릭터를 등록하고, 좋아요·리뷰·랭킹을 통해 팬들이 소통하는 커뮤니티 플랫폼이다.
누구나 캐릭터를 등록할 수 있고, 부적절한 게시물은 관리자가 신고 접수를 통해 삭제할 수 있다.
React + TypeScript 프론트엔드와 Node.js + Express 백엔드, PostgreSQL 데이터베이스로 구성된다.

## 2. 사용자 시나리오

### 2.1 일반 사용자 — 캐릭터 탐색 및 좋아요
1. 캐릭터 목록 페이지에 접속한다.
2. 작품별 필터 또는 검색어로 캐릭터를 찾는다.
3. 캐릭터 카드를 클릭해 상세 페이지로 이동한다.
4. 좋아요 버튼을 눌러 캐릭터를 응원한다 (비로그인 시 로그인 페이지로 이동).
5. 랭킹 페이지에서 인기 캐릭터 순위를 확인한다.

### 2.2 일반 사용자 — 캐릭터 등록
1. 로그인 후 캐릭터 등록 페이지로 이동한다.
2. 작품명(기존 작품 선택 또는 새로 추가), 캐릭터 이름, 설명, 이미지, 명대사를 입력한다.
3. 등록 완료 후 캐릭터 상세 페이지로 이동한다.
4. 본인이 등록한 캐릭터는 마이페이지에서 수정할 수 있다.

### 2.3 일반 사용자 — 리뷰 및 신고
1. 캐릭터 상세 페이지에서 한줄평(리뷰)을 작성한다.
2. 부적절한 캐릭터(도배, 저작권 침해, 욕설 등)를 발견하면 신고 버튼을 눌러 사유를 선택/입력한다.
3. 신고 완료 후 "신고가 접수되었습니다" 안내를 받는다 (중복 신고는 1회만 반영).

### 2.4 관리자 — 신고 처리
1. 관리자 계정으로 로그인한다.
2. 관리자 대시보드에서 신고 접수 목록을 확인한다 (신고 사유, 신고 횟수, 대상 캐릭터).
3. 신고 내용을 검토한 뒤 해당 캐릭터를 삭제하거나, 문제없다고 판단되면 신고를 "반려" 처리한다.
4. 삭제 시 관련 좋아요/리뷰/신고 기록도 함께 정리된다.

## 3. 기능 요구사항

### 3.1 인증

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-AUTH-01 | 이메일과 비밀번호로 회원가입할 수 있다 | O |
| F-AUTH-02 | 회원가입 시 닉네임을 입력한다 | O |
| F-AUTH-03 | 이메일과 비밀번호로 로그인할 수 있다 | O |
| F-AUTH-04 | 로그아웃할 수 있다 | O |
| F-AUTH-05 | 앱 재시작 시 로그인 상태가 유지된다 (JWT 토큰 복원) | O |
| F-AUTH-06 | 비밀번호는 8자 이상, 영문·숫자 포함이어야 한다 | O |
| F-AUTH-07 | admin 역할은 회원가입으로 생성할 수 없고 DB에서 직접 설정한다 | O |

### 3.2 작품 및 캐릭터

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-WORK-01 | 작품 목록을 조회할 수 있다 | O |
| F-WORK-02 | 캐릭터 등록 시 기존 작품을 선택하거나 새 작품을 추가할 수 있다 | O |
| F-CHAR-01 | 전체 캐릭터 목록을 조회할 수 있다 | O |
| F-CHAR-02 | 작품별로 캐릭터를 필터링할 수 있다 | O |
| F-CHAR-03 | 캐릭터 이름으로 검색할 수 있다 (부분 일치) | O |
| F-CHAR-04 | 캐릭터 카드에 이름, 작품명, 이미지, 좋아요 수가 표시된다 | O |
| F-CHAR-05 | 좋아요 수는 likes 테이블에서 실시간으로 계산된다 | O |
| F-CHAR-06 | 로그인한 사용자는 누구나 캐릭터를 등록할 수 있다 | O |
| F-CHAR-07 | 본인이 등록한 캐릭터만 수정할 수 있다 | O |
| F-CHAR-08 | 본인이 등록한 캐릭터를 삭제할 수 있다 | O |

### 3.3 캐릭터 상세

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-DETAIL-01 | 캐릭터 상세 페이지에서 설명, 이미지, 명대사를 확인할 수 있다 | O |
| F-DETAIL-02 | 좋아요를 누르거나 취소할 수 있다 | O |
| F-DETAIL-03 | 한줄평(리뷰)을 작성할 수 있다 | O |
| F-DETAIL-04 | 본인이 작성한 리뷰를 삭제할 수 있다 | O |
| F-DETAIL-05 | 캐릭터를 신고할 수 있다 (사유 선택 + 상세 내용) | O |
| F-DETAIL-06 | 동일 사용자가 같은 캐릭터를 중복 신고해도 신고 건수는 1회만 반영된다 | O |

### 3.4 랭킹

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-RANK-01 | 좋아요 수 기준 인기 캐릭터 랭킹을 조회할 수 있다 | O |
| F-RANK-02 | 작품별 랭킹 필터를 적용할 수 있다 | O |

### 3.5 마이페이지

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-MY-01 | 내가 좋아요 누른 캐릭터 목록을 조회할 수 있다 | O |
| F-MY-02 | 내가 등록한 캐릭터 목록을 조회할 수 있다 | O |
| F-MY-03 | 내가 작성한 리뷰 목록을 조회할 수 있다 | O |
| F-MY-04 | 닉네임과 프로필 이미지를 수정할 수 있다 | O |

### 3.6 신고 및 관리자

| ID | 요구사항 | 필수 |
|----|---------|------|
| F-REPORT-01 | 사용자는 부적절한 캐릭터를 신고할 수 있다 | O |
| F-ADMIN-01 | 관리자는 전체 신고 목록을 조회할 수 있다 (신고 사유, 누적 횟수) | O |
| F-ADMIN-02 | 관리자는 신고된 캐릭터를 삭제할 수 있다 | O |
| F-ADMIN-03 | 관리자는 신고를 반려(기각) 처리할 수 있다 | O |
| F-ADMIN-04 | 관리자는 전체 사용자 목록을 조회할 수 있다 | O |
| F-ADMIN-05 | 관리자는 플랫폼 통계를 조회할 수 있다 (사용자 수, 캐릭터 수, 신고 수) | O |
| F-ADMIN-06 | 캐릭터 삭제 시 연관된 좋아요/리뷰/신고 기록도 함께 삭제된다 | O |

## 4. 비기능 요구사항

| ID | 요구사항 |
|----|---------|
| NF-01 | 인증은 JWT 토큰 기반으로 처리한다 |
| NF-02 | 비밀번호는 bcrypt로 해싱하여 저장한다 |
| NF-03 | API는 RESTful 설계를 따른다 |
| NF-04 | 한국어 UI를 기본으로 한다 |
| NF-05 | 좋아요 수는 DB에서 실시간 집계한다 |
| NF-06 | 캐릭터/리뷰 삭제 권한은 서버에서 검증한다 (본인 또는 admin) |
| NF-07 | .env로 민감정보를 관리하고 Git에 커밋하지 않는다 |

## 5. 화면 구성

### 5.1 랜딩 페이지
- 히어로 섹션 (서비스 소개 + CTA 버튼)
- 실시간 인기 캐릭터 TOP 3

### 5.2 캐릭터 목록 페이지
- 작품 필터 탭 + 검색창
- 캐릭터 카드 그리드

### 5.3 캐릭터 상세 페이지
- 캐릭터 정보 (이름, 작품명, 설명, 이미지, 명대사)
- 좋아요 버튼
- 리뷰 작성 폼 + 목록
- 신고 버튼 (모달: 사유 선택)

### 5.4 캐릭터 등록/수정 페이지
- 작품 선택(또는 신규 작품 입력), 이름, 설명, 이미지 URL, 명대사 입력 폼

### 5.5 랭킹 페이지
- 좋아요 순 캐릭터 순위 리스트
- 작품별 필터

### 5.6 마이페이지
- 내가 좋아요한 캐릭터 / 내가 등록한 캐릭터 / 내가 쓴 리뷰 (탭 전환)
- 프로필 수정 폼

### 5.7 로그인/회원가입 페이지
- 이메일, 비밀번호, 닉네임 입력 폼
- 로그인 / 회원가입 탭 전환

### 5.8 관리자 대시보드
- 신고 목록 (대상 캐릭터, 사유, 신고 횟수, 처리 버튼)
- 사용자 목록
- 플랫폼 통계
