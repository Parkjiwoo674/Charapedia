# 보안 점검 결과 — Charapedia

일정표의 "보안 점검(입력 검증, 환경변수 관리 등)" 항목을 정리한 문서이다. 각 항목은 실제 DB를 띄워 자동 테스트로 확인했다.

## 1. 인증·계정
| 항목 | 적용 내용 | 위치 |
|---|---|---|
| 비밀번호 저장 | bcrypt(salt 12)로 해시해서 저장, 평문 저장 없음 | authController |
| 로그인 상태 | JWT(7일), 서버가 매 요청마다 토큰 검증 | middleware/auth.js |
| 이메일 인증 | 인증된 이메일로만 계정 생성(미인증 계정이 DB에 없음) | authController, email_verifications |
| 인증번호 | 암호학적 난수(crypto.randomInt) 6자리, 10분 유효 | utils/mailer.js |
| **인증번호 무차별 대입 방지** | 인증번호는 이메일당 **5번까지만** 입력 가능. 시도 횟수를 먼저 DB에서 원자적으로 올린 뒤 비교하므로 동시에 여러 번 보내도 5번을 넘지 못함 | authController.verifyCode |
| 로그인 오류 메시지 | 아이디/비밀번호 중 무엇이 틀렸는지 알려주지 않음 | authController.login |
| 회원탈퇴 | 현재 비밀번호 확인 후 처리, 업로드한 사진 파일도 삭제 | authController.deleteAccount |

## 2. 요청 제한 (rate limit)
| 대상 | 한도 |
|---|---|
| 전체 API | 15분에 1000번 |
| 로그인 | 15분에 30번 (초과 시 올바른 비밀번호도 429) |
| 인증메일 발송(회원가입·비밀번호 찾기) | 10분에 10번 |
| 인증번호 확인 단계 | 15분에 60번 |

초과하면 429와 안내 메시지를 돌려준다. 한도는 `src/middleware/rateLimit.js` 맨 위에서 바꿀 수 있다.

## 3. 입력값 검증 (서버에서 다시 검사)
- 아이디: 영문·숫자·밑줄 4~20자 / 닉네임 20자 / 비밀번호 8~64자(영문+숫자) / 이메일 형식·100자 / 인증번호 숫자 6자리
- 이메일은 공백 제거·소문자로 정리해서 저장
- 캐릭터: 이름 100자, 특징 2000자, 명대사 500자, 이미지 주소 2000자 + **http(s) 주소만 허용**(javascript: 등 차단)
- 작품: 작품명 200자, 작가명 100자 / 리뷰 300자 / 신고 상세 500자
- 문자열이 아닌 값(배열·객체)을 보내 서버를 오류로 만드는 요청은 400으로 처리
- SQL은 모두 `?` 파라미터 바인딩 사용(SQL 인젝션 방지), 화면은 React가 출력값을 자동 이스케이프(XSS 방지)

## 4. 권한
- 수정은 등록자 본인만, 삭제는 본인 또는 관리자만(서버에서 확인, 화면 버튼 숨김에 의존하지 않음)
- 관리자 API는 로그인 + admin 권한 둘 다 필요(`requireAdmin`)
- admin은 회원가입으로 만들 수 없고 DB/스크립트로만 지정

## 5. 파일 업로드(프로필 사진)
2MB 제한, JPG/PNG/WEBP/GIF만 허용, 파일 내용의 시그니처까지 확인(이름만 .png인 가짜 파일 차단), 랜덤 파일명 저장, 경로 조작 방어, `nosniff` 헤더로 제공.

## 6. 서버 설정
- helmet으로 보안 헤더 적용(X-Powered-By 제거, nosniff, CSP, HSTS 등)
- CORS: `CLIENT_URL`에 적은 주소(쉼표로 여러 개)만 허용
- 요청 본문 100KB 제한, 깨진 JSON은 400
- 서버 시작 시 `NODE_ENV=production`인데 `JWT_SECRET`이 짧거나 기본값이면 **시작 거부**
- `.env`는 git에서 제외, 예시는 `.env.example`로 제공 / 에러 응답에는 내부 정보를 담지 않음

## 7. 알려진 한계 (솔직하게)
- 요청 제한은 서버 메모리에 저장해서 서버를 재시작하면 초기화된다.
- JWT는 비밀번호를 바꿔도 만료(7일) 전까지 유효하다. (토큰 폐기 기능은 구현하지 않음)
- 비밀번호 찾기·회원가입 단계에서 "가입된 이메일/아이디인지"가 응답으로 드러난다. 사용 편의를 위해 감수했다.

## 8. 확인 방법
`charapedia-backend`에서 서버를 켠 뒤 `docs/05_test_plan.md`의 항목을 수동으로 확인하고, 아래 동작을 시연할 수 있다.
- 틀린 인증번호를 5번 입력 → "입력 가능 횟수를 초과했어요" 안내
- 로그인 실패를 30번 넘게 반복 → 429 안내
- 이미지 주소에 `javascript:alert(1)` 입력 → 거부
